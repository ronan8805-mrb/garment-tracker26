FINAL REPLIT BUILD PROMPT
Industrial Laundry Garment Tracking System (QR-Based)

Build a web-based track-and-trace application for an industrial laundrette that manages garments for multiple factories. The system must be QR-code driven, scan-based, and designed for high-volume, real-world laundry operations.

1. CORE PRINCIPLES (NON-NEGOTIABLE)

The system is scan-driven only

No manual status editing

No “in transit” status

A garment is only considered somewhere when it is scanned IN

All QR codes are generated by the laundrette admin only

Factories have very limited access

2. USER ROLES & ACCESS
🧺 LAUNDRETTE ADMIN (FULL CONTROL)

Can see all factories

Can see all garments

Can see all scan events

Can generate QR codes

Can print and email PDFs

Can run reports

Can create factory accounts

🏭 FACTORY USER (LIMITED – ONE ACCOUNT PER FACTORY)

One login per factory (no sub-users)

Can ONLY:

Scan garments OUT of factory

Scan garments IN to factory

View their own garments (read-only)

Cannot:

Generate QR codes

See other factories

See laundry operations

Edit or delete anything

3. LOCATIONS & STATUS MODEL (VERY SIMPLE)

There are ONLY TWO VISIBLE LOCATIONS:

At Factory

At Laundry

Status is derived from the last IN scan only.

Rules:

Factory IN → Status = At Factory

Laundry IN → Status = At Laundry

OUT scans do NOT change visible status

No “in transit” anywhere in the UI.

4. SCAN POINTS (THE ONLY ACTIONS)
Factory

Factory OUT (sending to laundry)

Factory IN (receiving from laundry)

Laundry

Laundry IN (receiving from factory)

Laundry OUT (sending back to factory)

Each scan records:

Garment ID

Location (Factory / Laundry)

Direction (IN / OUT)

Timestamp

User

Scan events are immutable.

5. LAUNDRETTE ADMIN: CREATE FACTORY + GARMENTS
Step 1: Create Factory Profile

Fields:

Factory Name

Factory Code (short, e.g. HF)

Location (optional)

Status (Active / Inactive)

Creates:

Single factory account + login credentials

Step 2: Define Garments (SIZE-BASED)

Admin adds garments in rows:

Garment Type	Size	Quantity
Lab Coat	S	80
Lab Coat	M	160
Lab Coat	L	180
Lab Coat	XL	80

System auto-calculates total (e.g. 500 garments).

Step 3: Generate QR Codes (BULK)

When admin clicks “Generate Garments & QR Codes”:

System must:

Create one record per physical garment

Generate one unique Garment ID per garment

Generate one QR code per garment

Default status = At Factory

Garment ID format (recommended):
HF-LC-M-000123

6. QR CODE RULES (IMPORTANT)

QR code contains ONLY the Garment ID

No URLs

No JSON

No extra data

Human-readable text printed under QR

QR codes must be compatible with NETUM CS7501 scanners (keyboard/HID mode).

7. QR CODE PDF OUTPUT (CRITICAL FEATURE)

After QR generation, system must:

Generate ONE print-ready PDF

Containing all QR codes

A4 format by default

Multiple labels per page

Suitable for label printers / print shops

Each label includes:

QR code

Garment ID (text)

Factory code

Size

Admin options:

Download PDF

Email PDF to printer

Re-download later

Example file name:

HoneyFactory_QR_Codes_500_Garments_2026-01-25.pdf

8. SCANNING UI REQUIREMENTS

Auto-focused scan input

Accepts scanner input (acts like keyboard)

Handles Enter key automatically

Visual confirmation per scan

Error handling:

Unknown QR → error

Wrong factory → error

Duplicate scan in batch → warning

9. BATCH SCANNING + REPORT PRINTING

When scanning OUT (laundry or factory):

Batch Scan Mode

Live counter (e.g. “Scanned: 200 items”)

Scrollable list preview

Actions:

Finish & Save Batch

Finish, Save & Print Report

Printable Batch Report (PDF)

Report includes:

Laundrette name

Batch ID

Date & time

From / To

Factory name

Total items

Summary by garment type & size

Optional full item list

Sign-off section

Reports must be:

Printable

Downloadable

Re-printable later

10. DASHBOARDS
Factory Dashboard

Total garments

At Factory

At Laundry

Read-only list

Laundrette Dashboard

All factories

All garments

All scan history

Batches & reports

Filters by factory, date, status

11. DATA & TECH REQUIREMENTS

Web app (desktop-first, mobile-friendly)

Secure authentication

Role-based access control

Database tables for:

Users

Factories

Garments

QR codes

Scan events

Scan batches

Reports

Scan log is the single source of truth

12. FUTURE-READY (DESIGN FOR, DO NOT BUILD YET)

RFID support

Multiple laundrettes

SLA timing

CSV exports

API access

If it wasn’t scanned, it didn’t happen.
